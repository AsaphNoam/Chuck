# Operate agents

Use Chuck to launch a role in a project, then supervise the resulting agent by its Chuck identity. Configuration edits affect future launches; a running or persisted session retains its frozen project, role, permission, directory, backend, model, and provider-resolution snapshot until the operator explicitly chooses a lifecycle action that changes it. Reasoning effort and fast mode belong to the same runtime identity but are not frozen that way: on a running chat agent the operator applies either one immediately from the chat header, without stopping the process or rebuilding the conversation, and the applied value becomes the stored one that resume, clone, and the archive carry.

- Launch through the dashboard or `chuck <role>@<project>`. A bare matching launch may resume a single inactive session; `chuck agent launch` always creates a new one and `chuck agent resume` targets an exact id. Use explicit new/resume controls when Chuck reports ambiguity.
- The operator CLI uses the running local service and does not start it automatically. Its readable or JSON results report accepted, held and queued actions rather than completed model work. An interrupted mutation may have an unknown result; inspect current state before retrying, and reuse an identical caller receipt only where the operation supports one. Transcript follow can be interrupted without cancelling or stopping the agent. These are local operator controls; they do not replace the scoped authority of Chuck's agent-facing tools.
- Chat provides the managed transcript and inline Chuck controls. Terminal runs the supported provider CLI while preserving Chuck persistence and lifecycle hooks. Chuck agent-to-agent messaging and durable task execution require chat agents; terminal agents do not participate. Fast mode is a chat-only capability offered for models that declare it, so a terminal launch asking for it is refused rather than started at normal speed.
- A running chat agent whose provider session advertises permission modes (for Claude, modes such as Manual, Accept Edits, Plan Mode, Don't Ask or Bypass Permissions) can be moved between exactly those modes from the chat header or `chuck agent mode`, without restart; the shown mode is what the provider reports, and a refused change keeps the reported mode. This live mode is not persisted: resume, runtime switch and relaunch start in the provider's default, and the session's frozen Chuck permission policy is unchanged. A mode that skips provider prompts means no approval request reaches Chuck to show.
- Chat messages, including Steer, can carry images and files. Chuck delivers them with the text as one message in their attached order: images arrive as image input on image-capable runtimes, and other files as immutable uploaded copies at an exact local path that the agent reads with its normal tools under its existing permissions. Acceptance means the message was accepted, not that every file was read. Chuck refuses rather than silently dropping an attachment the runtime cannot take. Sent copies stay in Chuck's conversation storage until the conversation is deleted, and Clone carries its own copies; originals are never modified.
- Chat opens local links to regular UTF-8 text files on demand, including absolute paths and readable files outside the project or inside `.git`; source and rendered-Markdown selections can become annotations in the conversation's existing pending tray. This viewer does not browse directories, write files, or make local file reads available through remote control.
- Calling one of Chuck's own agent-facing tools never waits for a human approval, whatever permission policy the session froze at launch, and no approval deadline applies to it — with one exception: asking Chuck to stop another agent. Every other tool keeps its normal gate — file access, shell commands, network fetches, and provider- or user-configured servers — so a held approval is about that work, not about Chuck's control plane. Unless a deployment configures a deadline, a gated call waits indefinitely: the agent stays waiting with the tool unexecuted until a person decides, the turn is cancelled, or it is stopped. Nothing auto-denies it back into motion, so do not plan around a timeout.
- The Claude Code or Codex executable is not part of that frozen snapshot. Every process start — launch, resume, wake, clone, switch — uses the backend's current provider choice: the operator's installed CLI by default, or Chuck's bundled copy when the operator chose it in Settings. A provider update or Settings change therefore applies at the next start and never alters a running agent. A missing or too-old provider fails that start with the repair to make; Chuck does not switch providers, start a replacement conversation, or replay the prompt on its own.
- Resume keeps the frozen session configuration by default. Runtime switch changes the selected interface/backend/model while preserving the logical session; a provider change may use a bounded one-shot history primer. Switch never carries a fast-mode change, because that setting is applied on the running agent instead. A reported fast mode is the setting Chuck applied and not a live reading from the provider, so an agent whose provider has since suspended it can still read as on.
- The seeded `default` role has no persona (shown as **No persona**; `chuck default@<project>`) and is the fresh-install default; it is always Chuck aware. A custom persona with **Chuck aware agent** turned off launches agents without Chuck's shared operating context and the pointer to this skill, while keeping every tool, permission and the installed skill. The choice is frozen per agent across resume, wake, clone and switch; later persona edits affect only later launches.
- Stop ends the live process without deleting its durable session. Archive and resume remain available for known sessions.
- A chat agent may ask Chuck to stop one other agent, with a reason. Chuck itself holds that request until the user approves that specific request once; no provider permission mode, skipped permissions, role or claim of earlier approval stands in for that decision, and your turn waits for it. Approval is permission to try, not a result: the tool reports whether the agent actually stopped, was already stopped, or whether the outcome is unknown. A denied, cancelled or stale request is final — do not retry it automatically — and an approval never carries over to a restarted target or a later turn. A stopped agent keeps its history and can be woken later; Stop is not Cancel, which only interrupts the current turn. This is a gate on Chuck's tool, not process isolation: local operator controls keep their existing same-machine trust.
- **Quota interruptions:** Settings → Tasks contains the global **Auto continue after quota reset**
  toggle. It defaults on, including when an older `config.json` omits the field. Turning it off
  persists the policy and cancels pending continuations; if cancellation is incomplete, Chuck reports
  that while keeping the saved policy off. A quota interruption remains visible in the dashboard/chat.
  Current Claude/Codex adapters do not provide a reset timestamp with verified units, so Chuck shows
  **Reset time unknown** and does not schedule a timed continuation from those provider signals. Use
  the normal Resume/Send controls when you choose to continue manually. Re-enabling the toggle does
  not restore a cancelled schedule.
- Role and project files are user-owned configuration. Project resources live in Chuck's project-scoped resource directory and are composed into supported launches; do not treat state database files as editable configuration.
- A project's working directory may be a Git worktree Chuck created and owns. Everything inside one project — agents, tasks, pipeline stages — shares that checkout, so parallel isolation means another project, not another directory inside one. The checkout is disposable and is recreated from its recorded branch when a launch finds it missing; the branch, commits, project, and session identities are the durable things. Removing an owned checkout only ever happens as an explicit operator choice.

Read the active tool or CLI help for exact inputs and availability. A prompt cannot grant an interface, provider capability, permission, or lifecycle operation that Chuck does not expose.
