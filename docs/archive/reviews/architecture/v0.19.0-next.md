## ARCH-v020-1: saved-tab refusal and recovery feedback have no empty-reader surface

**Must fix; localized/easy.** FS-03.R103/R105, TS-08.R141/R144 and INV §8 require readable
recovery/refusal feedback. `fileTabs.open` records total/byte-limit refusal in the store, but
the sole `notice` renderer is `TabStrip` in `ui/src/features/fileTabs/FileTabs.tsx`.
`ReaderWorkspace`, `ThinkTankPage` and phone `AgentScreen` mount their reader only when tabs
exist. A new owner has no strip: with 500 saved tabs in other conversations/rooms, its first
file open is refused without any visible explanation. Damaged saved data likewise resets all
owners to empty while leaving its recovery message without a renderer until a later successful
open. The 500 tabs are retained correctly; this is silent refusal/recovery feedback, not file loss
or a file-authorization escape.

The focused `architectureNotice.probe.test.tsx` component reproduction at the reviewed commit
failed as expected: store refusal and the retained count of 500 both passed, then the visible
`role=status` expectation failed. Its accessible DOM contained only the transcript and file link.
The temporary source was removed from the product tree and retained at
`/private/tmp/chuck-v020-notice.probe.test.tsx` for the fixer. This is component DOM proof, not a
physical-device or rendered layout receipt.

Smallest repair: render the shared notice from a mounted workspace/app surface independent of
tab membership, preserving deduplication, dismissal, current limits and file authority. Retain a
regression that seeds ten owners with fifty legitimate saved descriptors each, opens a file in
an empty eleventh owner through the real transcript link/controller/store, and expects visible
500-tab/close-a-tab feedback with no new read or eviction. A damaged-storage empty owner is the
same missing-renderer seam. Do not redesign storage or add automatic eviction.

## Independent bounded probe

`/private/tmp/chuck-v020-architecture-probe.mjs` imported the candidate's pure TypeScript codec,
admission reducer and asynchronous limiter through esbuild. It passed: 500 tabs across ten owners
round-trip; the 501st refuses without modifying the set; over-budget raw input is rejected before
parse; decoding and re-encoding strips injected `content`/`readAt` fields; four outstanding reads
remain counted while selected work waits; replacing a pending intent drops the superseded intent
and starts only the latest selected request. These are codec/scheduling claims, not browser,
server, physical-phone or native-provider proof.

The sampled 500-tab record used 194,536 UTF-16 bytes. Across 500 encoding iterations on the host,
p50 was about 0.10 ms and p95 about 0.46 ms; maximum was 208.63 ms during concurrent release
build/tests. This measures serialization only, not representative UI throughput, memory, provider
cost or end-to-end latency. No broad performance improvement is claimed.
