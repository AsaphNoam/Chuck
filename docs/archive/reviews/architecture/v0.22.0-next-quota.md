## Conclusion

The feature has multiple confirmed broken integration boundaries, beyond the investigated missed
refusal. Three additional Must-fix defects concern human cancellation, checking the wrong provider
selection, and rejecting a successful check. Two Worth-fixing defects concern shared-dispatch delay
and an orphaned unstarted claim. Existing NESTED-QUOTA-1 retains its original owner and native
incident evidence. The new grouped fix recommendation is medium — Codex Terra or Claude Opus.

The strongest architecture is below detection: one durable per-agent episode, revision/token
claims, domain-specific task/room admission, same-session continuation, bounded checks, and
uncertain-delivery fencing. Existing real-store/fake-provider tests support those mechanisms.
The weakest parts are evidence normalization and evidence equivalence at the provider boundary.
The ordinary turn and isolated check implement different terminal-success rules; a selection hash
omits native settings that determine the account/model actually tested. Cleanup I/O also runs on
the shared dispatch thread. These are architectural joins, not merely parser wording mistakes.

Repair the existing seams before considering a scheduler rewrite. Keep provider-owned evidence,
same-work ownership and explicit manual control. Unify completion semantics where the existing
ordinary path is already correct, establish effective selection equivalence or refuse it, and
move bounded cleanup I/O off shared admission. A wider replacement would add migration and replay
risk without addressing the provider signal that was lost in the field incident.

The current evidence does not establish a single cause for every reported unsuccessful recovery,
nor prove that any credentialed end-to-end recovery has succeeded. Existing live Claude/Codex
refusal-to-reset-plus-one-minute gates remain owed. Passing the internal scheduler fixtures cannot
substitute for that boundary proof.

## Confirmed findings

Full live findings and routing model are in `docs/features/HANDOFF.md`, ARCH-QUOTA. The receipt
references both that unit and the existing NESTED-QUOTA-1 owner.

1. **ARCH-QUOTA-1 — Must fix: accepted Cancel loses to late quota metadata.**
   `internal/runtime/quota.go:191–245` first sets cancelled, then attaches retained/result quota
   and overwrites it with error. Completion passes that evidence to `settleQuotaTurn`, allowing
   a fresh schedule after manual cancellation. TS-04.R86 explicitly preserves cancelled;
   FS-01.R43 forbids stale automation. Probe: `TestAuditQuotaResultAfterCancelKeepsCancelled`.
   Actual result: StopReason:error and nonnil Quota after successful `ChatRuntime.Cancel`.
   This is runtime/fake-wire proof; server-side scheduling is the traced consumer, not a separately
   observed real-provider reset dispatch. Fix verification must exercise that server consequence.
2. **ARCH-QUOTA-2 — Must fix: check authorization can cover a different model/account route.**
   `internal/runtime/quota_check.go:253–269,441–442` disables settings but omits their inherited
   model; `applySessionConfig` skips empty ModelID. The supported native-inherited contract uses
   empty ModelID (`internal/server/contract.go:14–20`, `internal/state/contract.go:55–60`).
   Probe `TestReviewQuotaCheckInheritedModelCannotProveSameModel` reports ready while emitted
   session/new contains neither model nor settings despite a configured source model.
   Independently, pinned SDK `resolveSettings` resolves opus with original source layers and no
   model with an empty source list. No credentialed effective-model claim is made.

   `internal/server/quota_check.go:32–43,82–103` hashes Env/Cwd, while creation rereads mutable
   Claude routing settings. `TestAuditRoutingEditAuthorizesDifferentProfile` launches route A,
   edits settings to B, observes B in the probe's actual session/new, then observes the unchanged
   key admit continuation of the original live conversation. These are one same-selection defect
   with two normal stimuli. FS-01.R49/R51, TS-04.R97 and TS-10.R46 govern. Authentication was fake;
   no live account was switched or contacted.
3. **ARCH-QUOTA-3 — Must fix: recovered retry warning falsely fails the isolated check.**
   `internal/runtime/quota_check.go:106–109,328–353` retains probe.failure on successful terminal
   completion. `internal/state/quota_checks.go:117,140–142` then holds check_failed; this is not
   merely another hourly retry. `TestAuditQuotaCheckRecoveredRetryWarning` fails with
   Outcome:failed/Cleaned:true. Pinned Codex `dist/index.js:30886–30909` emits and internally
   clears streaming retry warnings; `:30251–30258` clears on success. Its eventual successful
   prompt carries no failure metadata. Ordinary `quota.go:207–212` already honors that contract.
   TS-04.R86/R97 require the check to use terminal truth while preserving actual terminal errors.
4. **ARCH-QUOTA-4 — Worth fixing: cleanup delays all shared dispatch.**
   `quota_dispatch.go:16` performs synchronous cleanup before due admission. `quota_check.go:312–338`
   serially calls provider cleanup; runtime cleanup has a five-second RPC deadline. The same
   shared loop then handles task cleanup, pipelines, waits, timed starts and ready tasks
   (`task_dispatcher.go:41–52`). A real fake-provider subprocess that withholds initialize
   reproduces 5.005 seconds of delay to an unrelated due claim. Eight records can add roughly
   40 seconds, derived from the bounded batch and per-record timeout, not measured as an eight-row
   benchmark. Preserve exact cleanup/cursor ownership while removing I/O from shared admission.
5. **ARCH-QUOTA-5 — Worth fixing: failed policy reread leaves invisible admission limbo.**
   `quota_dispatch.go:106–108` and check admission `quota_check.go:219–221` return without settling
   an already durable claim on config read error. `TestAuditConfigReadFailureStrandsClaim` corrupts
   only that reread, restores the exact file, and finds the unstarted claim absent from due queries
   an hour later. Restart can repair it; ordinary sweeps cannot. Hold/defer the exact claim with
   a visible reason. FS-01.R44 and TS-10.R40/R43 govern. Fault-injection proof, not field attribution.
